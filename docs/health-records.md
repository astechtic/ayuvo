# Health Records — cross-platform contract

Plan: `/Users/macbook/.claude/plans/improve-workouts-flow-in-typed-pinwheel.md`. Shared files live in `shared/records/`; each platform embeds a verbatim copy and a parity test compares it with the shared file. Change the shared file first, then both platforms in the same change.

## 1. Rules that never bend
1. The imported original file is the source of truth. It is never modified or re-encoded; it is copied byte-for-byte into the records files root.
2. Import succeeds as soon as the original is copied and the `records` row is inserted. Every later stage is best-effort and may fail without removing the record.
3. AI output is a suggestion (`state = suggested`) and never overwrites `confirmed`, `user` or `rejected` values.
4. Nothing is split, merged, replaced or deleted without an explicit user action.
5. Records are excluded from iCloud backup, Android Auto Backup and the regular Drive `ayuvo-backup.zip`. They leave the device only through: the user's chosen AI provider (per the AI mode), explicit sharing, a user-saved `ayuvo-records` archive, or the Android opt-in Drive records backup.
6. Copy rule: never say records "never leave your device".

## 4. Phase 1 import behaviour
1. Stream-copy the source to `<files root>/<id>/original.tmp` while computing SHA-256; sniff the first 32 bytes; rename to `original.<ext>` (ext from the sniffed type: pdf, jpg, png, heic, webp, gif, txt, md, bin). Maximum file size 512 MB (larger → import refused with a message; nothing is kept).
2. Pasted text and notes are saved as `original.txt` (UTF-8) and one `record_pages` row (`page_index 0`, `text_source plain`).
3. Plain-text and Markdown files also get one `record_pages` row with their text (capped at 2 MB of text).
4. Insert the `records` row (`processing_status = saved`). Title: user-entered, else the filename without extension (underscores/dashes → spaces, trimmed), else `"<Type> — <date>"`, else "Untitled record".
5. Exact duplicate check: another record with the same `checksum_sha256` → show "This looks like an existing record" with Keep both · Replace · Merge · Cancel (Phase 1 implements Keep both, Cancel and Open existing; Replace/Merge arrive with Phase 2 review).
6. Background: page count (PDF), thumbnail (PDF page 1 / image downsample; text → none, the UI draws a text tile), basic metadata date (PDF `/CreationDate`, EXIF `DateTimeOriginal`, filename `yyyy-MM-dd|yyyyMMdd|dd-MM-yyyy` patterns) → `document_date` with `document_date_method = file_metadata`, precision `day`; when none, `document_date = NULL` and the timeline uses `created_ms`.
7. Index the FTS row: `title`, `notes_tags` (notes + tag names), `body` (page text), others empty in Phase 1. Folding: lowercase + strip diacritics (NFD, remove combining marks) on both write and query; query terms become `term*` joined by spaces (implicit AND).

## 5. Timeline ordering
`records.sort_date` = `document_date` when known, else the **device-local** calendar day of `created_ms` at import time. The app writes it on insert and on every `document_date` change (clearing the document date resets it to the local import day). Order: `ORDER BY sort_date DESC, created_ms DESC, seq DESC` (served by `idx_records_timeline`), keyset cursor `(sort_date, created_ms, seq)`, grouped by the month of `sort_date`. Archived records are hidden unless the Archived filter is on.

### 8.1 Write rule (`applyExtraction`, identical on both platforms)
Reference: `apply_extraction` / `normalize_value` / `derive_record` (vectors `apply_extraction.json`).
Normalized value (`normalize_value`): `norm(s)` = §10 `fold(s)`, then every maximal run of alphanumeric code points is a word (ASCII `a-z0-9`, or above U+007F a code point whose General_Category is `L*` or `Nd`), words joined by one space. Per key: date keys and `document_time` → the ISO string unchanged; `test_result` → `norm(value_json.name)` + `|` + `norm(value_json.value)`; `doctor_name` → `norm` without leading `dr`/`doctor`/`prof` words; `patient_name` → `norm` without leading `mr`/`mrs`/`ms`/`miss`/`master`/`mstr`/`baby`/`smt`/`shri`/`sri`/`kumari`/`kum`/`mx` words (at least one word is always kept); everything else, `medication` included (the drug name), → `norm(value_text)`.
New items are applied in their given order (earlier inserts of the same batch count as existing rows). For each extracted `(field_key, normalized value)`:
1. A row with that key and normalized value in `rejected`, `confirmed` or `user` → skip (action `skip_<state>`).
2. Else a row in `suggested` (the first one in row order) → update `value_text`, `value_json`, `method`, `evidence`, `source_page`, `source_bbox`, `confidence` only if the new confidence is strictly higher (`update`), otherwise `keep`.
3. Otherwise insert `suggested` (`insert`; the vectors name inserted ids `new-1`, `new-2`, … in insertion order — ports substitute their generated UUIDs in that order).
Nothing is ever overwritten across different values. **Conflict**: a single-valued key (every key except `test_result`, `diagnosis`, `symptom`, `medication`, `procedure`, `recommendation`) with ≥ 2 distinct normalized values among non-rejected rows; `doctor_name` rows whose `value_json.role` is `referrer` form their own slot (`doctor_name:referrer`), so a referring doctor never conflicts with the treating/signing doctor. Conflicts are listed sorted and shown side by side in review.
Record columns (`derive_record`). "Best row" of a key = non-rejected rows that are `user`/`confirmed` (any confidence) or have confidence ≥ 0.6, ordered by state (`user`, `confirmed`, `suggested`), then confidence descending, then row order:
- `record_type` / `category` / `type_confidence` / `type_method`: only when `type_method` is not `user` → the classification candidate (rules classifier and/or AI `record_type`) with the highest confidence (first one on ties); category = the type's default category (§3).
- `document_date` (+ `sort_date`, `document_date_precision` from `value_json.precision`, default `day`; `document_date_method` = that row's `method`): only when `document_date_method` is NULL, `import_time` or `file_metadata` → the best row of the first key present in `report_date`, `collection_date`, `prescription_date`, `discharge_date`, `visit_date`.
- `title`: only while the title is import-derived (the app compares it with the Phase 1 derivation; the vectors pass `title_is_derived`) → best `report_name`, else `"<Type label> — <best facility>"` with the English stored labels Lab Report, Prescription, Doctor Note, Discharge Summary, Imaging Report, Diagnostic Report, Medication List, Vaccination Record, Bill, Insurance, Note, Record (stored titles are never localized), else unchanged. Type columns are derived before the title.
User edits of those columns set their method to `user` and are never touched again.

## 9. Processing pipeline
Stages run in `processing_jobs.stage` order. Each stage commits its own transaction, advances `stage`, and bumps the store revision; a crash resumes at the stored stage. One record at a time, background priority.
`processing_status`: `queued` → `extracting_text` (text) → `analyzing` (classify … validate/highlights) → `ready`; `ai_pending_consent` while an `ask` record waits (all non-AI stages still run, the `ai` stage is revisited when the user decides); `failed_partial` when a stage failed permanently (`processing_error`: `text_unavailable`, `ocr_failed`, `ai_failed`, `ai_unavailable`, `protected_pdf`, `unsupported`). The record is always usable.
AI retries: 3 attempts at 30 s / 5 min / 1 h; offline → wait for connectivity (Android WorkManager `CONNECTED` constraint for the `ai` stage only; iOS `NWPathMonitor`); after the last attempt continue without AI.

### 9.1 Text
- PDF: text layer per page — Android `PdfRenderer.Page.getTextContents()` when `SdkExtensions.getExtensionVersion(Build.VERSION_CODES.S) >= 13`, else render + OCR; iOS PDFKit: line boxes built from per-character selections (`PDFPage.selection(for: NSRange)` bounds) grouped into words and split into cells at horizontal gaps wider than about one line height — `selectionsByLine()` merges table columns and is not used; `PDFPage.string` is only a fallback. A page whose text has fewer than 20 letters is rendered (long side 2000 px, via the render cache) and OCR'd. A text layer that returns no usable line positions (some Android builds return text without bounds, which glues table columns together) is treated the same way: the page is OCR'd for line boxes and the text layer is kept only as a fallback when OCR yields fewer letters.
- Images: OCR — Android ML Kit Text Recognition (Latin), iOS Vision `VNRecognizeTextRequest` (`.accurate`, language correction on). EXIF orientation applied; long side ≤ 3000 px.
- `record_pages.text`: lines joined by `\n` in reading order (by line box top, then left; a line joins an existing row when its vertical centre is within half of the taller box height of the row's line nearest to it in x (comparing with the nearest-in-x neighbour, not the row's first box, tolerates the ~1–2° skew of photographed pages); row lines are joined by two spaces left-to-right — this keeps lab table rows on one line). `blocks_json`: `[{"t":"line text","b":[x,y,w,h]}]`, normalized 0–1, origin top-left. `ocr_confidence`: mean line confidence or NULL.
- Text and Markdown records already have their page from import. Sequential pages, one bitmap in memory, cap 1,000 pages.

Sorting is stable everywhere.

### 9.3 AI stage
Runs when the resolved mode (§16) is `local` or `cloud` and at least one gap exists: record type below threshold; no date; no doctor or facility; body lines that look like results (contain a number + unit) but produced no `test_result`; prescription with no medication; consultation note, discharge summary or imaging report with no `diagnosis` and no `recommendation`. A record with no gap never calls AI (the optional AI summary highlight is generated only when AI runs anyway). Input: the page texts of the record (or segment), chunked by page, ≤ 12,000 characters per call for cloud and ≤ 2,500 for local; images only for pages with no usable text (cloud vision provider, or local Gemma one page per call; never Apple Intelligence). Prompt and response schema: `shared/records/ai_extraction.md` + `ai_extraction.schema.json`. Per-call max output tokens 3,000 (new optional parameter on the existing AI call; global setting unchanged).
Chunking (`ai_chunks`, vectors `ai_chunks.json`): each non-empty page is rendered `=== Page N ===\n<pfold text>` (N 1-based); a page longer than the limit is split at line breaks into consecutive blocks that repeat its header (a single over-long line is hard-cut); blocks are packed greedily, joined by a blank line, into chunks of ≤ 12,000 (cloud) / 2,500 (local) code points.
Validation (`ExtractionValidator` = `validate_ai(pages, ai_json, mode, today, date_order, image_pages)`, vectors `ai_validation.json`). `flat(s)` = `fold(s)` with runs of space/tab/newline collapsed to one space and trimmed; "contains(value, evidence)" = `" " + norm(value) + " "` is a substring of `" " + norm(evidence) + " "` (§8.1 `norm`); numbers = tokens `[0-9]+([.,][0-9]+)*` of the folded text with commas removed (`1,50,000` → `150000`).
1. Parse: an object is used as is; a string is cut from its first `{` to its last `}` and parsed; anything else, or invalid JSON (truncated output), → `error = parse_error` and nothing is kept.
2. `record_type` kept only when it is a §3 value; `record_type_confidence` clamped. `report_name` kept (confidence 0.7, `source_page` = first page that contains it) only when some page contains it.
3. Every item: `source_page` must be an integer 1…page count (else `missing_source_page` / `bad_source_page`) and is stored 0-based; `evidence` must be a non-empty string whose `flat` form is a substring of `flat(page text)` (`evidence_not_found`), except for a page listed in `image_pages` whose text is empty: those items are kept with confidence capped at 0.5.
4. Dates: `key` must be a date key (`unknown_key`); `value` `yyyy-MM-dd` (precision day) or `yyyy-MM` (precision month, stored `yyyy-MM-01`), a valid calendar date and plausible per §11 (`bad_date`); the evidence must contain that date by §11 at the same precision, where an ambiguous numeric date may be read in either day/month order (`date_not_in_evidence`).
5. Fields: `key` ∈ doctor_name, doctor_specialty, facility, department, patient_name, patient_age, patient_sex, diagnosis, symptom, procedure, recommendation, document_time; every number of the value must be in the evidence (`number_not_in_evidence`); the value must be contained in the evidence except for `patient_sex` (`value_not_in_evidence`).
6. Test results: name contained in the evidence; a value without numbers must be contained in the evidence; every number of the value must be in the evidence. `ref_text` whose numbers are not all in the evidence → null; `ref_low`/`ref_high` parsed from the kept `ref_text` with the §13 reference forms. `unit`: a units.json variant → canonical; else kept as given only if its fold is a substring of the folded evidence; else null. **The model's flag is ignored**: the flag is recomputed with §13 flag resolution from a printed marker directly after the value occurrence that follows the name in the evidence, else the printed range, else `unknown`.
7. Medications: name contained in the evidence and its numbers in the evidence; `strength`, `dose`, `frequency`, `duration`, `instructions` are kept only when contained in the evidence with all their numbers (else null); `form` only needs its numbers in the evidence (models write "tablet" for "Tab.").
8. Summary: dropped when any number in its text is absent from all page texts (`number_not_in_pages`); whitespace collapsed; > 400 code points → first 399 + `…`; `source_pages` filtered to valid pages, 0-based.
9. Confidence of every kept item: a number clamped to [0, 0.9] (missing or non-numeric → 0.5); `method` = `ai_local` / `ai_cloud`; `from_image` = the page was sent as an image (such items always trigger review, §15). Dropped items are reported as `{kind, index, reason}`.

## 10. Folding and classifier
- `fold(s)` (reference `fold`): (1) `\r\n`/`\r` → `\n`; (2) Unicode NFKD; (3) delete combining marks (General_Category `Mn`, `Mc`, `Me`) and U+00AD, U+200B, U+200C, U+200D, U+2060, U+FEFF; (4) per line, runs of spaces/tabs → one space, then trim spaces (NFKD has already turned NBSP, U+2000–U+200A, U+202F, U+205F, U+3000 into spaces); (5) lowercase **per code point without context** (Java `Character.toLowerCase(int)`; Σ → σ, never ς; a code point whose full lowercase mapping is longer than one code point is kept). Line count is preserved (blank lines stay). Effects: `µ` → `μ`, `²`/`³` → `2`/`3` (`10³/µL` → `103/μl`), `ﬁ` → `fi`, full-width digits → ASCII, `½` → `1⁄2`; `₹`, `×`, `≤`, `–`, `•`, arrows are unchanged. Phase 2 FTS indexing and queries use this definition (it supersedes the §4 NFD fold; the Phase 2 indexer rebuilds every row).
- `pfold(s)` ("printed fold") = the same steps without (5). It has exactly the same length as `fold(s)`, so offsets found in folded text slice the printed text. Values stored "as printed" and every rules `evidence` are `pfold` slices (diacritics removed, case kept).
- Cells: before step (4) each line is split on a tab or a run of ≥ 2 spaces (§9.1 joins OCR row cells with two spaces); the cells, trimmed and joined with one space, equal the `pfold` line. Cell spans stop values (patient names, doctor names) and give lab rows their column boundaries.
- Classifier (`classify(pages)`): `head` = the first 25 non-empty folded lines of the first page of the analysed range (whole record, or a boundary segment); `body` = every non-empty folded line of every page. A rule scores its weight once when its pattern matches **within a single line** of its scope (patterns never span lines). `record_types.json` patterns use `\b \d \s \w` with Unicode semantics: Python default str patterns, NSRegularExpression default, JVM unit tests `Pattern.UNICODE_CHARACTER_CLASS` (Android's ICU-backed `Pattern` already treats these classes as Unicode; the classifier vectors must pass in both places). Besides those classes, record_types patterns may use one-character fixed-width lookarounds (the prescription frequency rule is wrapped in `(?<![-/])…(?![-/])` so `hs-CRP` or `TSH-HS` never count as `hs`). Vector text only uses ASCII plus µ/μ, ₹, ×, ≤, –, —, •, ↑, ↓ and superscripts, where these semantics agree.
- Best type = highest score, ties → earlier in `types`; `second` = the highest score among the other types. The type wins when `best ≥ threshold` and `best − second ≥ margin`; otherwise `other`. Confidence = `round2(min(0.95, 0.55 + 0.10 × min(best − second − margin, 3) + 0.05 × min(best / threshold, 2)))` with `round2(x) = floor(x × 100 + 0.5 + 1e-9) / 100` (range 0.60–0.95); `other` → confidence `0`. It grows with the lead beyond the margin and with the absolute score: a lead exactly at the margin gives at most 0.65, so such a record always gets review (§15, bar 0.7), while any lead of margin + 1 gives at least 0.70, so a clean document of any type needs no review because of its type. Category = the type's `category`. Output also carries `scores` for every type in the file.
- `personal_note` is never produced by the classifier: it comes from the import source `note`. A free-text note classifies as `other`.
- Filename/user title is NOT classifier input (sender metadata is untrusted).

## 11. Dates
Reference `extract_dates(pages, record_type, today, date_order)`; all matching on folded lines.
- Forms (one leftmost-longest, non-overlapping pass per line; equal start and length → ISO, numeric, `d month y`, `month d y`, `month y`): `yyyy-mm-dd` with the same separator `-`, `/` or `.` twice; `d/m/yyyy`, `d-m-yyyy`, `d.m.yyyy`, `d/m/yy`, `d-m-yy` (same separator twice; a 2-digit year needs `/` or `-`); `d[st|nd|rd|th][ ./-]month[.][ ,./'-]*(yyyy|yy)` (`12-Sep-26`, `5th September 2026`, `12sep2026`); `month[.][ ./-]d[st|nd|rd|th][ ,./-]*yyyy` (`Sept 5, 2026`); `month[.][ ,'./-]*yyyy` (precision month, stored as the 1st). Months: full English names, 3-letter abbreviations and `sept`. Digits are never adjacent to another digit on either side. An invalid calendar date consumes nothing.
- 2-digit years → `2000 + yy` when `yy ≤ (today.year + 1) mod 100`, else `1900 + yy`.
- Numeric `a/b/y` order: `a > 12` → day-first; `b > 12` → month-first; both > 12 → not a date; otherwise `date_order` (`dmy` default, `mdy` for month-first regions, e.g. US).
- Plausibility: ≥ 1900-01-01, and ≤ today + 2 years (same month/day; Feb 29 → Feb 28) for `follow_up_date`, ≤ today + 1 day for every other key.
- Labels (folded, whole words; the tables are `_DATE_LABELS` in the reference, abbreviated here):
  - `dob`: dob, d.o.b, date of birth, birth date, born → the date is dropped.
  - `ignore`: printed (on), print date, generated (on), registered (on), registration (date), received (on), valid till/upto/until, expiry, exp, mfg, manufactured, lmp, edd → dropped (they are not document dates and would only create conflicts).
  - `collection_date`: collected (on/at), collection (date), date of collection, sample date, sample collected (on), sample collection (date), specimen collected, drawn (on), coll. date, date of sample.
  - `report_date`: reported (on), report date, date of report, reporting date, released (on), authenticated (on), authorised/authorized (on), result date, approved on, verified on.
  - `visit_date`: visit date, date of visit, consultation date, date of consultation, opd date, visited on, seen on, appointment date, encounter date.
  - `prescription_date`: rx date, prescription date, date of prescription.
  - `admission_date`: date of admission, doa, admitted (on), admission date. `discharge_date`: date of discharge, dod, discharged (on), discharge date.
  - `follow_up_date`: follow up/follow-up/followup (on/date/visit), review on, review date, next review, next visit (on), revisit (on), f/u, come back/again on, next due (on/date), due on.
  - typed (→ the type default key, 0.9): invoice/bill/receipt date, date of issue, issue date, certificate date, date of vaccination, vaccination date, vaccinated on, date of dose, dose date, date administered, study/exam/scan/test date, date of study/examination/test/procedure/surgery/service, procedure date, claim date, service date.
  - bare (→ the type default key): `date`, `dated`, `dt` — only in the head; confidence 0.8 for `prescription` and `consultation_note` (they print one date), 0.6 for every other type.
  - Type default key: `report_date` for lab/imaging/diagnostic, `visit_date` for consultation note, `prescription_date` for prescription, `report_date` otherwise.
- Same-line label: the segment of the line between the previous date on that line and this date is searched; the label whose match ends last wins (then the longest, then table order). The text between that label and the date must be ≤ 24 characters of punctuation and the words on, at, dt, date, dated, time, and, of, is (`Collected On : `, `Collection Date & Time : `) — a `follow_up_date` label may instead be followed by any ≤ 32 characters (`Next due: MMR Dose 2 on`). Otherwise the date counts as unlabeled. Confidence 0.9.
- Previous-line label: only when the date line has no label at all and the previous non-empty line of the page has no date. Labels are matched per cell of that line; if their count equals the number of dates on the date line they pair in order (`Sample Collected On  Reported On` over two dates), else a label ending that line (only connector words/punctuation after it) pairs with the first date. Confidence 0.8 (bare labels keep their 0.8/0.6).
- Unlabeled: only dates in the head; only the first one is kept, as the type default key with confidence 0.6, and only when no labelled item has that key and no labelled item has that date.
- Relative follow-up (a line with no absolute follow-up date): `(follow up|review|revisit|come back|next visit|see me)` + up to 4 words + ` after|in N days|weeks|wks|months|mths` → the best other date (§8.1 `document_date` key order, highest confidence, earliest) + N days / 7N days / N calendar months (day clamped); confidence 0.7; no base date → dropped.
- De-duplication: per `(key, date)` the highest confidence wins (earliest on ties); output in position order (page, line, column).
- Every date item has `value_json {"precision": "day"|"month"}`.
- `document_time`: on the line of the primary date (§8.1 order, highest confidence, earliest), the first `h:mm[:ss]` (hours 0–23) after that date and before the next date on the line, with optional `am`/`pm`/`a.m.`/`p.m.` (12 am → 00, 12 pm → 12; hours outside 1–12 with am/pm are dropped) → `HH:mm`, confidence 0.7, `value_json` null.

## 12. Fields (rules)
Reference `extract_fields(pages, record_type)`: every key below except dates and `test_result`. Output de-duplicated by `(key, role, normalized value)` keeping the highest confidence, in position order.
- `doctor_name`:
  - Label form (folded): `consultant|consulting doctor|treating doctor|attending doctor|doctor|physician|surgeon|referred by|referring doctor|ref. by|ref by|ref. doctor|ref. dr` + optional space + `:`/`-`, optional `dr.` → a name; confidence 0.85; labels starting `ref` give `value_json {"role":"referrer"}`. A value starting `self` is skipped.
  - Prefix form: `Dr`/`DR`/`dr` followed by `.` or a space (not preceded by a letter, not inside a label match) → a name; 0.85 when the line is in the head, else 0.7.
  - Name = printed text within the current cell matching `[A-Z][A-Za-z'.-]*( [A-Z][A-Za-z'.-]*){0,5}` (so it stops at a comma, digit, `(`, a lowercase word or a cell boundary), cut before the first token that is a qualification printed in capitals (`MBBS`, `MD`, `DM`, `M.B.B.S`, …) or a cut word (consultant, reg, mobile, hospital, clinic, department, …; `_NAME_CUT`), trailing `.-'` removed; needs a token with ≥ 2 letters. The value never includes `Dr.`.
  - At most one referrer and one primary doctor per record: the highest confidence candidate of each role (earliest on ties); the primary is dropped when it normalizes equal to the referrer.
- `doctor_specialty` (primary doctor only): on the rest of the name's line, else on the next non-empty line, the printed span from the first to the last match of the qualification/specialty list (`_RE_SPECIALTY`: mbbs, md, ms, dm, mch, dnb, mrcp, frcs, bds, mds, dgo, dch, facc, mrcog, frcp, dmrd — dotted forms accepted — cardiologist, physician, pediatrician/paediatrician, gynaecologist/gynecologist, obstetrician, orthopaedic/orthopedic (surgeon), dermatologist, neurologist, endocrinologist, pathologist, radiologist, general/internal medicine, diabetologist, nephrologist, pulmonologist, gastroenterologist, psychiatrist, ophthalmologist, oncologist, urologist, surgeon); qualifications of ≤ 3 letters count only when printed in capitals (`Ms.` is a title); a `)` closing an open `(` is included (`MD (Internal Medicine)`); 0.7.
- `facility`: head lines of page 1 (0.8), then heads of later pages (0.6); the first line ≤ 80 characters matching `hospital(s)|clinic(s)|medical/health/diagnostic cent(er|re)|diagnostics|laboratory|laboratories|labs|path lab(s)|pathology|imaging|scans|nursing home|polyclinic|healthcare|health care|institute|medical college|pharmacy|chemist(s)|medicos|medicals` and not containing report, department, dept, referred, ref, consultant, patient, name, test, result, reference, range, sample, specimen, collected, date or dr (and not starting with `Dr`). A leading `label:` is removed (`Hospital: City Care Hospital, Nagpur`); the value is cut at the first comma when the facility word comes before it, or when the line has ≥ 3 commas (the address); all-caps words with ≥ 2 letters are title-cased (`ST. MARY'S HOSPITAL` → `St. Mary's Hospital`); needs ≥ 3 letters.
- `department`: the first line with `department of X` / `dept. of X`, or `X department` where X starts the line or follows `, ; : | ( -`; X = 1–4 words → 0.7.
- `patient_name` (head of page 1 only, first match): strong labels `patient name`, `patient's name`, `name of (the) patient`, `pt. name` + `:`/`-` anywhere; or, when the line, the previous or the next head line has patient context (`age`, `sex`, `gender`, `uhid`, `mrn`, `yr(s)`, `year(s)`, `y/o`, `34 y/m`, `34/f`), the weak labels `patient:`/`name:` or a title `mr|mrs|ms|miss|master|mstr|baby|smt|shri|sri|kumari|kum`. Value: after an optional title, words `[a-z][a-z.'-]*` separated by a space or `, ` (≤ 6, within the cell), cut at age, sex, gender, uhid, mrn, id, dob, ref, date, reg, no, ip, op, lab, sample, y, yr(s), years, m, f, male, female, bed, ward, phone, mobile; trailing `.,-'` removed; ≥ 2 letters. `DOE, JANE M` → `DOE, JANE`. 0.75.
- `patient_age` (first head line): `age[/sex] [:-] N [unit]`, or `N [y|yrs|years] / m|f|male|female`, or (on a line with patient context) `N years|yrs [old]`; N ≤ 120 → `"N years"`, or `"N months"` / `"N days"` when the unit says so. `patient_sex`: `sex|gender [:-] [N y /] male|female|other|transgender|m|f`, or the `N/M` form → `male` / `female` / `other`. Both 0.75.
- `report_name` (only for `lab_report`, `imaging_report`, `diagnostic_report`, `other`): head lines of page 1 up to (not including) the first section label line (§12 sections); skip the facility line, table headers, lines with > 8 words, lines not starting with a letter, lines that parse as a lab row, `label:` lines, lines with `:` or a date. The first line matching a weight ≥ 3 rule of the lab/imaging/diagnostic types in `record_types.json`, or containing `panel`, `profile` or `function test(s)` (`LIPID PANEL`), → confidence 0.8; else the first line containing the word `report` with ≤ 6 words and no digits → 0.7. Value: printed, trimmed of ` .:-`, all-caps words of ≥ 4 letters title-cased and all-caps `AND OF THE FOR WITH IN ON TO` lowercased after the first word (`COMPLETE BLOOD COUNT (CBC)` → `Complete Blood Count (CBC)`).
- Sections (all types): a label line starts (after an optional bullet `1.`, `1)`, `-`, `•`, `*`, `·`, `>`) with a section label followed by `:`/`-`/`–` and text (inline), or by nothing (a heading); `c/o` may also be followed directly by a space. Labels: `diagnosis` ← (provisional|final|clinical|working|discharge|differential) diagnosis/diagnoses (on discharge), impression, dx; `symptom` ← (chief|presenting) complaint(s), c/o, presenting symptom(s), symptom(s); `procedure` ← procedure(s)/operation(s)/surgery (done|performed); `recommendation` ← advice (on discharge), discharge advice, advised, recommendation(s), plan (of care), instructions, suggested, suggestion(s), follow up advice. Stop-only labels: history, hpi, examination, o/e, vitals, investigation(s), medication(s), treatment (given), rx, course in hospital, condition at discharge, findings, technique, conclusion, interpretation, clinical history/indication, allergies, comment(s), note(s), remark(s), signature, medicines.
  - Collected text: the inline text, then following lines (blank lines directly after a heading are skipped) until a blank line, any label line, a generic `label:` line (`[a-z][a-z0-9 /().&'-]{0,30} ?:` at line start), a signature line (`Dr …`, signature, signed, radiologist, pathologist, end of report, authorised signatory) or 10 lines. Recommendation sections skip medication lines.
  - Items: split on `;` (diagnosis, procedure, recommendation) or `,`/`;` (symptom) and per line; a leading bullet and trailing `. , ; : - –` are trimmed; kept when 2…limit characters with a letter (diagnosis 120, symptom 80, procedure 120, recommendation 160). Confidence diagnosis 0.75, others 0.7.
  - Standalone recommendations (types other than lab_report, bill, insurance): lines starting `repeat `, `review `, `follow up `, `follow-up `, `consult ` (≤ 160 characters) → 0.7.
- `medication` (prescription, discharge summary, medication list, consultation note only), one per line:
  - Form line: optional index (`1.`, `1)`, `-`, `•`, `*`, `·`, `>`, `rx`) + form word + `.` or space. Form words → `value_json.form`: tab/tabs/tablet(s) → tablet; cap/caps/capsule(s) → capsule; syp/syr/syrup → syrup; inj/injection → injection; oint/ointment → ointment; cream; gel; drop(s) → drops; inhaler; sachet(s) → sachet; susp/suspension → suspension; lotion; spray; powder; soln/solution → solution; neb/nebulisation → nebulisation; respule(s) → respules.
  - Fallback line (no form word): 1–4 words starting with a letter, then a strength directly after them, and also a frequency, duration or instruction on the line; a `%` strength never qualifies (`HbA1c 7.8 %`).
  - Parts (first match of each in the rest of the line; overlapping later matches dropped): strength `N[.N][/+N…] (mg|mcg|μg|ug|gm|g|ml|iu|unit(s)|meq|%)[/N ml|g]`; frequency `a-b-c[-d]` (digits, `1/2` allowed), `od` (also `0d`), `bd`, `bid`, `tds`, `tid`, `qid`, `qds`, `hs`, `qhs`, `sos`, `prn`, `stat`, `qd`, once/twice/thrice daily, once/twice/thrice/three times/four times a day, once weekly, weekly, daily, at night, every N hours, qNh; duration `x|×|* N day(s)|d|week(s)|wk(s)|w|month(s)|mth(s)|m`, `for N days|weeks|months`, `N days|weeks|months`; instructions after/before food, after/before meal(s), with food/meals/milk/water, (on) empty stomach, (at) bedtime, after breakfast/lunch/dinner, before breakfast/dinner, apply locally, local application, if needed/required, when required, as needed; dose `N tab(s)|tablet(s)|cap(s)|capsule(s)|puff(s)|drop(s)|sachet(s)|tsp|teaspoon(s)`.
  - Name = printed text from after the form word (or the line start) to the first part or ` - `, ` (`, ` — `, ` – `, trimmed of ` -–:,.(`; 2+ letters, ≤ 60 characters, ≤ 6 words (`Dolo 650` keeps its number). For syrup/suspension/drops/solution an `N ml` strength without `/` becomes the dose.
  - `value_json` = `{name, strength, form, dose, frequency, duration, instructions}` as printed (null when absent); confidence 0.8 with a strength or frequency, else 0.6.
- `location`: city/address is not extracted in Phase 2.

## 13. Lab rows
Reference `parse_lab_rows(pages, record_type)` / `parse_lab_line`; units `shared/records/units.json` (`match_unit`).
- Applies to every line when the type is `lab_report`/`diagnostic_report`, or when ≥ 3 lines contain a number immediately followed (optional space) by a unit.
- Skipped lines: table headers (no digit and ≥ 2 of test(s), parameter(s), investigation(s), result(s), unit(s), reference, ref, range, interval, value(s), flag, method, observed, biological, normal, description, name).
- Split: after an optional leading bullet, the name ends either at the first cell boundary (cell mode, tried first) or before any later token (token mode, left to right); the first split whose name is valid and whose tail parses wins.
- Valid name: trailing ` :.=-–_` trimmed; starts with `a-z`; ≤ 60 characters; ≥ 2 letters; no token made only of digits and `.,:;/-` (`Plot 12, Sector 5`); no `< > = ≤ ≥` (interpretation tables such as `Non-diabetic < 5.7`); first word not a demographic/meta word (`_META_FIRST`: age, sex, name, patient, uhid, sample, ref, date, time, page, phone, mobile, report, collected, dr, bill, invoice, amount, …); contains no date.
- Tail grammar (folded tail; printed slices at the same offsets): value, then in this order and each optional: flag, unit, flag, reference, unit, flag.
  - Value: `N-N` (integers ≤ 3 digits, a range value such as `4-6 /hpf`); or optional comparator `< > <= >= ≤ ≥` + number (`1,50,000` / `11,800` groups or `13.2`) that must be followed by the end, a space, `(`, `[`, a unit, or an attached flag `h l hh ll * ↑ ↓` followed by a space/end (`11.2L`, `0.9*`); or a qualitative word: positive, negative, reactive, non-reactive, not detected, detected, nil, absent, present, trace, normal, abnormal. `value_num` = the number with commas removed (comparator kept only in `value`).
  - Flag (followed by a space or the end): critical high, critical low, critical, (high), (low), (h), (l), [h], [l], high, low, hh, ll, h, l, `*`, `↑↑`, `↓↓`, `↑`, `↓`.
  - Unit: the longest folded units.json variant at that position followed by the end, a space or `) ] } , ;` → canonical spelling.
  - Reference: `(…)`/`[…]` containing a digit (its inside may be a range form below) or, unbracketed and followed by a space/end, `a - b` (`-`, `–`, `—` or `to`), `< <= ≤ up to/upto less than below b`, `> >= ≥ more than greater than above a`. `ref_text` = printed, brackets included.
  - Leftover text: rejected when it has a digit or > 4 words; for a qualitative value without a reference, ≤ 3 words become `ref_text` (`Protein  Trace  Nil`); otherwise it is tolerated only when the row has a unit or a reference (method column `Photometry`).
  - Rejected rows: a range value without a unit; a comparator value without a unit; a name + plain number with no unit, reference or flag and a name of > 4 words.
- Flag resolution (`computable` = numeric value without comparator and not a range value):
  1. Explicit marker: `hh`/`↑↑`/critical high → `critical_high`; `ll`/`↓↓`/critical low → `critical_low`; high markers → `high`; low markers → `low`; `*` → `low`/`high` when computable and outside the printed range, else `abnormal`; `critical` → `critical_low`/`critical_high` when computable and below/above the range, else `abnormal`.
  2. Qualitative value: `abnormal` → `abnormal`; when both the value and a one-word `ref_text` belong to a family (negative: negative, nil, absent, non-reactive, not detected, normal; positive: positive, reactive, present, detected, trace, abnormal) → `normal` if the families match, else `abnormal`; otherwise `unknown`.
  3. Range value `a-b` with a range: `high` if `a > ref_high`, `low` if `b < ref_low`, `normal` if inside, else `unknown`.
  4. Computable with `ref_low`/`ref_high`: `low` if value < ref_low, `high` if value > ref_high, else `normal` (bounds inclusive; `<200` stores `ref_high 200`).
  5. Otherwise `unknown`.
- Confidence: name + value + unit + reference 0.9; with one of unit/reference 0.8; name + value only 0.6 (qualitative 0.7).
- `value_json` = `{name, value, value_num, unit, ref_text, ref_low, ref_high, flag}`; rows de-duplicated by §8.1 normalized value. Multi-line rows (name and value on different lines) and two results on one line are not parsed in Phase 2 (AI covers them).

## 14. Boundaries (multi-record PDFs)
Reference `detect_boundaries(pages, today, date_order)` → `{page_scores, segments, propose}`. Only for `page_count ≥ 3` (otherwise one segment, no scores). Per page: `type` = the best type by score alone (margin ignored; ties → file order) when its score ≥ threshold, else none; `numbering` = `page n of m` / `page n/m` / `pg. n of m` in the first or last 3 non-empty lines, or such a line that is exactly `n of m`/`n/m`; `head words` = §8.1 words of the first 5 non-empty lines; `names` = the page's `patient_name` (§12 on that page alone); `dates` = §11 date values found in the page's head, excluding `follow_up_date`; `report` = the page's `report_name`. For each page `i ≥ 1`, against the current segment (started at the last break) and page `i − 1`:
- +3 `page_one_of`: page `i` numbering is `1 of m`.
- +2 `previous_last_page`: page `i − 1` numbering is `n of n`.
- +3 `type_change`: page `i` type and the segment type both exist and differ (the segment type is the first page type found in the segment).
- +2 `head_change`: Jaccard(head words of `i`, of `i − 1`) < 0.3 (two empty sets → 1).
- +2 `patient_or_date_change`: page `i` has names and the segment has names and they share none, or the same for dates.
- +2 `report_name_change`: page `i` and the segment both have a report name (the segment keeps its first) and they differ.
- +1 `previous_blank`: page `i − 1` has < 20 letters (the blank page stays with the earlier segment).
- −3 `continuation`: page `i` numbering is `n of m` with `n > 1`, or its first non-empty line starts with `continued`, `contd`, `cont'd` or `cont.`.
A break is proposed when the score ≥ 5; otherwise page `i` joins the segment (its names and dates are added). Segment output: `page_start`/`page_end` (0-based inclusive), `record_type` = §10 on the segment's pages, `title` = §12 `report_name` of the segment, else `"<Type label> — <facility>"`, else the type label (§8.1 labels), `confidence` = `round2(min(0.95, 0.5 + 0.05 × score))` of the break that starts it (the first segment uses the first break's score; a single segment uses 0). ≥ 2 segments → `propose = true` and one `split_proposals` row. Nothing is split without the user.

## 15. Highlights, review, near duplicates
- Highlights (`build_highlights(fields, summary)`, `method = rules`; rows in state `rejected` are ignored; each output `{section, text, position, field_index, source_page, confidence}`; identical texts within a section are kept once):
  - `important`: `test_result` rows with flag low/high/critical_low/critical_high/abnormal. Text `"<name>: <value>[ <unit>] — below the report reference range"` (low), `— above the report reference range` (high), `— marked critical on the report` (critical_*), `— marked abnormal on the report` (abnormal), with `name`, `value`, `unit` from `value_json`. Order: critical first, then low/high, then abnormal; inside a group by relative distance descending (`(ref_low − v)/|ref_low|` for low, `(v − ref_high)/|ref_high|` for high, the plain difference when the bound is 0, 0 when unknown), then input order. Max 8.
  - `medications`: `"<name>[ <strength>][ · <frequency>][ · <duration>]"`, input order, max 10.
  - `recommendations`: the recommendation texts, input order, max 5.
  - `summary`: only the validated AI summary (§9.3), label "AI summary — verify against the original report", > 400 code points → first 399 + `…`, `field_index` null.
- Review (`review_status(record, rows, pending_split, pending_duplicate)` → `{status, reasons}`; `record` carries `record_type`, `type_confidence`, `type_method`, `document_date`, `processing_error`, `ocr_confidence`, `review_status`), reasons in this order:
  1. `type_uncertain`: `type_method` ≠ `user` and (`record_type` = `other` or `type_confidence` < 0.7).
  2. `no_date`: `document_date` is NULL.
  3. `conflict:<slot>`: a §8.1 conflict slot with at least one `suggested` row.
  4. `low_confidence:<key>`: a `suggested` row of `report_name`, `doctor_name`, `facility` or any date key with confidence < 0.8 (keys sorted).
  5. `split_pending`, `duplicate_pending`.
  6. `text_failed`: `processing_error` is `text_unavailable` or `ocr_failed`; `ocr_low_confidence`: the record's mean OCR line confidence (`record_pages.ocr_confidence` averaged over OCR'd pages; unknown → not raised) is < 0.6 (handwriting, poor scans).
  7. `ai_image_item`: a `suggested` row with `from_image`.
  Any reason → `needs_review`; else `reviewed` if the record was `reviewed`, else `none`. When the record is already `reviewed`, reasons 1, 2 and 6 (both) are not re-raised (the user has seen them); reasons tied to unconfirmed rows or pending proposals reopen review. Confirming everything in the review sheet sets `reviewed`. Rules confidences are chosen so a clean labelled report needs no review (labelled dates 0.9, facility 0.8, head doctor 0.85, panel report name 0.8).
- Near duplicates (after text; reference `dhash_hex`, `minhash_signature`, `signature_similarity`, `near_duplicate`, vectors `hashing.json`):
  - `phash`: the first page render/image is converted to greyscale `(299 R + 587 G + 114 B) / 1000` and resized to 9 columns × 8 rows (platform resampling; it does not need to be bit-exact because matching uses a Hamming threshold); bit (row r, column c ≤ 7) = 1 when `gray[r][c] > gray[r][c+1]`, taken row-major with row 0 column 0 as the most significant bit, printed as 16 lowercase hex digits.
  - `text_signature`: words = §8.1 words of `fold(all page texts)`; shingles = the distinct runs of 5 consecutive words joined by one space (1–4 words → one shingle of all words; 0 words → signature `""`). FNV-1a 64: `h = 0xcbf29ce484222325`, for each byte `h ^= b; h *= 0x100000001b3 (mod 2^64)`. For each shingle `base = fnv1a64(utf8(shingle))`; slot `s` (1…64) = `fnv1a64(le64(base), h = fnv1a64(le64(s)))` (start from the hash of the 8 little-endian bytes of `s`, then feed the 8 little-endian bytes of `base`); the signature keeps the unsigned minimum per slot, printed as 16 lowercase hex digits joined by `,`.
  - Similarity = equal slots / 64 (0 when either signature is empty). Candidate: both pHashes present, Hamming ≤ 6 and (similarity ≥ 0.9 or both signatures empty) → reason `phash`, score = similarity (or `1 − hamming/64` for empty texts); else similarity ≥ 0.95 → reason `content`, score = similarity; scores `round2`. Exact `checksum` duplicates stay the Phase 1 import-time prompt.

Otherwise no AI, `processing_error = ai_unavailable`, detail note "On-device AI isn't set up — details found without AI" with a link to the model setup.
  - `cloud`: the configured BYOK provider (text provider for text, vision provider for image pages; local providers selected as primary count as local). No key → no AI + note "Add an AI provider to use online AI".
  - `ask`: stage `ai` waits with `awaiting_consent = 1`, status `ai_pending_consent`; the record detail and Needs Review show "Use AI to find more details?" — On this device (if available) / Online AI · <provider> (if configured) / Not now. The choice applies to that record only; "Apply to all waiting records" is offered when > 1 wait. "Not now" clears the wait (`awaiting_consent = 0`, stage continues without AI) and shows a small "Find more details with AI" action later.
  - `off`: `ai` stage skipped.
- Status label on detail: `ai_mode_used` local → "Processed on this device"; cloud → "Processed using online AI · <provider display name>"; none → "Not processed by AI". Rules-only details still show their method badges.

## 17. Universal search (Phase 2)
`RecordQueryParser.parse(text, today, dateOrder) -> RecordQuery` (pure; reference `parse_query`; vectors `test-vectors/query_parser.json`, `today = 2026-09-15`, a Tuesday). Output: `{terms, date_from, date_to, record_types, flags, doctor, facility, favorites, needs_review, archived, source, chips, match}`.
- Tokens: `fold(text)` (newlines → spaces); full dates found by §11 (precision day, `dateOrder`) become date tokens; the rest are §8.1 words (so `x-ray` → `x`, `ray`; `Dr.` → `dr`). Tokens are consumed left to right; at each position the first rule that applies wins.
- Date specs (`spec`): a full date (that day); `<month> <yyyy>` (that month); `<yyyy>` 1900–2100 (that year); `today`; `yesterday`; `this|current week|month|year` (the whole calendar period; weeks run Monday–Sunday); `last|past|previous week|month|year` (the previous calendar period); `last|past|previous N days|weeks|months|years` (rolling: `today − N units` … `today`, months/years calendar-clamped); `<month>` alone → the most recent month with that name that is not in the future (`june` → 2026-06, `october` → 2025-10), but a bare 3-letter abbreviation or `may` is a month only after a preposition.
- Date phrases (1) `from|between <spec> [to|and|till|until <spec>]` → `spec₁.start … spec₂.end` (a lone `from <spec>` = `in <spec>`); `since <spec>` → from `spec.start`; `after <spec>` → from `spec.end + 1 day`; `before <spec>` → to `spec.start − 1 day`; `in|during <spec>` → the spec range; (2) a bare spec → its range. Several date phrases intersect (latest `date_from`, earliest `date_to`); an open side stays null. Dates are inclusive on `sort_date`.
- States (2): `shared with me`, `received` → `source = received`; `needs review`, `to review` → `needs_review`; `favorite(s)`, `favourite(s)`, `starred` → `favorites`; `archived` → `archived`.
- Type phrases (3), longest listed first: blood test(s)/blood report(s)/test report(s)/lab report(s)/lab/labs → `lab_report`; doctor note(s), consultation(s), visit(s) → `consultation_note`; discharge summary/summaries, discharge → `discharge_summary`; x ray(s), xray(s), ct scan(s), mri scan, scan(s), imaging, mri, ct, ultrasound, usg → `imaging_report` (the single words mri, ct, xray, ultrasound, usg are also kept as terms); report(s) → `lab_report`, `diagnostic_report`, `imaging_report`; prescription(s), rx, medicine(s) → `prescription`; bill(s), invoice(s), receipt(s) → `bill`; insurance, claim(s) → `insurance`; vaccine(s), vaccination(s) → `vaccination_record`; note(s) → `personal_note`. `record_types` is output in §3 order.
- Flag phrases (4): out of range, abnormal, abnormality, abnormalities → `abnormal`; low → `low`; high, elevated, raised → `high`; critical → `critical`. Output order abnormal, low, high, critical.
- People (5): `doctor|dr <name>` → `doctor`; `at|hospital <name>` → `facility`; `<name>` = up to 3 following word tokens that are not stop words, state/type/flag words or the start of a date spec. Without a name the word is just a stop word.
- Stop words (6), removed: a, an, the, my, of, with, where, was, were, is, are, from, for, in, on, show, find, all, me, and, or, to, by, at, any, which, that, had, has, have, please, get, list, records, record, documents, document, files, file, last, latest, recent, this, since, before, after, between, doctor, dr, hospital. Every other token is a term (first occurrence kept, in order).
- `chips`: one `{kind, text}` per recognised phrase in order (`date`, `type`, `flag`, `doctor`, `facility`, `favorites`, `needs_review`, `archived`, `source`), `text` = its folded tokens joined by spaces. `match` = terms as `term*` joined by spaces (FTS4 implicit AND), or null when no term remains. Analyte phrases (`hemoglobin was low`, `hba1c above 7`, `high cholesterol`) and bare analyte aliases are handled by the Phase 3 rules in §23, which run before flags.
- `flags` filter: records having a `test_result` field (state ≠ rejected) whose `value_json.flag` matches: `abnormal` = any of low/high/critical_low/critical_high/abnormal; `low` = low or critical_low; `high` = high or critical_high; `critical` = critical_low or critical_high. Several flags are OR-ed. `value_json` is always written as compact JSON (no spaces) with keys in the §8 order, so implementations may match `"flag":"<value>"` textually. Analyte conditions: §23.
- Unrecognized-heavy queries (≥ 2 remaining non-stopword terms and zero FTS hits) may use `AiQueryRewriter` when mode allows: sends only the query text; response must be a `RecordQuery` JSON validated against the enumerations; shown as removable chips. With `ask` it's a "Search smarter with AI" row; with `off`/unset nothing.
- FTS columns (Phase 2 indexer): `title`; `people` = doctor names, specialties, facility, department, patient name; `clinical` = type label, report name, test names, diagnoses, symptoms, medications, procedures; `body` = page texts; `notes_tags` = notes + tag names; `highlights` = highlight texts. All folded. Rejected fields excluded.
- Ranking: BM25 computed from `matchinfo(records_fts, 'pcnalx')` with column weights title 5, clinical 3, people 3, highlights 2, notes_tags 2, body 1 (k1 1.2, b 0.75), plus recency boost `0.15 × max(0, 1 − days_since(sort_date)/730)`. Snippet from `snippet(records_fts, '[', ']', '…', -1, 12)` on the best column.

A row below confidence 0.6 that is not `user`/`confirmed` is not a best row.

  1. No observation has this `field_id`: insert one unless the field is `rejected` (vector ids `obs-1`, `obs-2`, … in insertion order; ports substitute UUIDs).   3. Observation still `suggested`: every `_OBS_SYNC_KEYS` column (mapping, values, unit, canonical, ranges, flag, method, confidence, state, source, evidence) is recomputed from the field — so confirming the field confirms the observation, after which it no longer follows the field.
  4. Any non-rejected observation whose `observed_date_method` is not `user` takes the current `observed_date` (a corrected record date reaches confirmed and user-edited observations too).
  Output `{observations, actions, panels}`: existing rows keep their order and ids, inserts are appended; `actions` = `{action: insert|update|reject|keep, id, field_id}`; `updated_ms = now_ms` on every changed row. A user edit of an observation never touches the field.

On confirmation, every non-rejected observation with `analyte_id` NULL whose `test_name_keys(raw_name)` contain the key gets that analyte, `analyte_method = user_alias` and a recomputed canonical value (state unchanged). The observation the user mapped is edited with §24.
- Entities (`rebuild_entities(fields)`), rebuilt whenever a record's fields change: primary doctor = §8.1 best non-rejected `doctor_name` row without `value_json.role = referrer` (role `doctor`, `specialty` = best `doctor_specialty` value); referrer = best row with that role (role `referrer`); facility = best `facility` row (role `facility`). One entity per `(kind, normalized_name)` (the same person as doctor and referrer is one entity with two `record_entities` rows). The store upserts by `(kind, normalized_name)`, keeps an existing `display_name` and fills a NULL `specialty`.
  - Doctor display name: `pfold`, whitespace collapsed, cut before the first `,` or `(`, trimmed of ` .-`; a glued `Dr.Name`/`Prof.Name` first token is split; leading tokens whose letters are `dr`, `doctor`, `prof`, `professor` and trailing tokens whose letters are a qualification (`_ENTITY_QUALIFICATIONS`: the §12 qualification list plus mrcgp, fcps, facp, frcpath, dpm, dortho, dlo, dvd, dnbe, fnb, fracs, mams; `M.B.B.S.` counts) are removed while more than one token remains; trailing `.-'` trimmed. `normalized_name` = §20 `analyte_words` of the display name (`A.K. Sharma` = `AK Sharma` = `ak sharma`).
  - Facility display name: `pfold`, whitespace collapsed, trimmed of ` ,.-|`. `normalized_name`: `analyte_words`; per word hospitals→hospital, clinics→clinic, laboratories/laboratory/labs→lab, diagnostics→diagnostic, centre/centres/centers→center, pathlabs→pathlab, speciality/specialities/specialties→specialty, and pvt, private, ltd, limited, llp, inc, and are dropped; then adjacent pairs join left to right: health care→healthcare, path lab→pathlab, multi specialty→multispecialty, super specialty→superspecialty, poly clinic→polyclinic; a leading `the` is dropped (one word always stays).
- `record_links`: `a_id < b_id` (string order) — one row per pair. `kind`: `follow_up`, `prescription_for`, `same_episode`, `previous_report`, `related`, `split_from`; `origin`: `user`, `suggested`; `status`: `suggested`, `accepted`, `rejected`; `reasons_json` = the §22 reasons array. ## 20. Analyte catalog (`shared/records/analytes.json`)
- Envelope `{"format":"ayuvo-analytes","version":1,"analytes":[…]}` (162 entries). Entry keys: `id` (snake_case, unique), `display_name`, `category` (`ANALYTE_CATEGORIES`: hematology, iron, vitamins, diabetes, lipids, liver, kidney, electrolytes, thyroid, cardiac, inflammation, coagulation, hormones, tumor_markers, urine, serology, pancreas, other), `panels[]` (`PANEL_IDS`: cbc, iron_studies, vitamins, diabetes, lipid, lft, kft, electrolytes, thyroid, cardiac, coagulation, hormones, urine_routine, urine_albumin, serology, pancreas), `kind` `numeric`|`qualitative`, `canonical_unit` (a `units.json` canonical spelling, or null), `decimals` (required for numeric, display only), optional `metric_registry_id`, `units[]` `{unit, factor, offset}` (canonical = value × factor + offset; every `unit` a `units.json` canonical spelling, factor > 0; the canonical unit listed with factor 1, offset 0), `aliases[]`; optional `loinc` (none shipped yet). `scripts/records_contract_check.py` enforces all of this.

Removing them never leaves zero words (the original words are kept). `total`, `free`, `direct`, `indirect`, `fasting`, `random`, `absolute`, `count` and `ratio` are never method words: where a plain name means the total (bilirubin, cholesterol, T3, T4, PSA, testosterone, calcium) the catalog lists both spellings as aliases.
- `test_name_keys(name)` (most specific first, duplicates removed): `k1` = `analyte_words(fold(name))`; `k2` = the same after deleting bracketed segments (`(…)` and `[…]`, nesting of the same bracket counted, an unclosed bracket runs to the end); `k1m` = `k1` without method words; `k2m` = `k2` without method words. `normalize_test_name(name)` = `k1m` (the `analyte_user_aliases` key). Examples: `Glucose, Fasting (FBS)` → `glucose fasting fbs`, `glucose fasting`; `Sr. Creatinine (Jaffe)` → `sr creatinine jaffe`, `sr creatinine`, `creatinine`.
- `map_analyte(name, panels, user_aliases, unit, qualitative)` → `{analyte_id, method, key, normalized_name, candidates}`:
  1. User alias: the first key (in key order) present in `user_aliases` whose analyte exists → `user_alias`.
  2. Catalog: the first key that is an alias key. A unique alias → that analyte (`catalog`). A shared alias → disambiguation below; unresolved → unmapped with `candidates` = the sharing analytes (the UI asks "Which test is this?"). Later keys are not tried once a key matched.
  3. No key matched → unmapped (`key` null). Never fuzzy or edit-distance matching.
  - Disambiguation (each step runs only while ≥ 2 candidates remain; a step leaving exactly one decides, one leaving none is skipped): (a) unit — the canonical spelling of `unit`, or `%` when the name itself contains `%` and no unit was given, is in the analyte's units (dimensionless numerics also accept `ratio`); (b) kind — `qualitative` when the value has no number, `numeric` otherwise (skipped when unknown); (c) panels — the analyte lists a detected panel; (d) urine rule — without a detected `urine_routine`/`urine_albumin` panel, `urine`-category analytes drop out.
  - Shared aliases (`ANALYTE_SHARED_ALIASES`; the check recomputes them from the file and requires each pair to be separable by disjoint unit sets, kind, the urine rule or a panel of its own): `neutrophils`/`neutrophil`/`neut` (and the same for lymphocytes, monocytes, eosinophils, basophils) → `_pct` vs `_abs` by unit; `rdw`, `red cell distribution width` → `rdw_cv` (%) vs `rdw_sd` (fL); `tc` → `wbc_count` (cbc) vs `cholesterol_total` (lipid, mg/dL); `rbc`, `red blood cells` → `rbc_count` vs `urine_rbc`; `wbc` → `wbc_count` vs `urine_pus_cells`; `leukocytes`, `leucocytes` → `wbc_count` vs `urine_leukocyte_esterase`; `glucose`, `sugar` → `glucose` vs `urine_glucose`; `protein` → `total_protein` vs `urine_protein`; `albumin` → `albumin` vs `urine_protein` (urine routine prints protein as "Albumin"); `bilirubin` → `bilirubin_total` vs `urine_bilirubin`; `creatinine` → `creatinine` vs `urine_creatinine`.
  - Decisions: direct and calculated LDL (and HDL) are one analyte; bare `Glucose`/`Blood Sugar` is its own analyte `glucose` (timing unknown), separate from fasting/post-prandial/random; `Urine Albumin` means microalbumin; an ambiguous differential without a unit stays unmapped.
- `detect_panels(texts, test_names)` → panels in `PANEL_IDS` order: a panel whose heading phrase (`_PANEL_KEYWORDS`, in `analyte_words` form) occurs as a whole-word run in `analyte_words` of any text (report names), or which ≥ 3 distinct analytes list, counting only names that `map_analyte(name)` maps with `catalog` and no context (unresolved shared aliases count for nothing). Headings: cbc — complete blood count, cbc, hemogram, haemogram, full blood count, fbc, blood count; iron_studies — iron studies/profile/panel, anemia/anaemia profile; vitamins — vitamin profile/panel, vitamin b12, vitamin d; diabetes — diabetes/diabetic profile, diabetes panel, glucose tolerance, blood sugar, hba1c, glycated, glycosylated; lipid — lipid(s), lipid profile/panel; lft — liver function, lft, hepatic function, liver panel/profile; kft — kidney/renal function, kft, rft, renal/kidney profile, renal panel; electrolytes — electrolyte(s); thyroid — thyroid, tft; cardiac — cardiac, troponin; coagulation — coagulation, prothrombin, pt inr; hormones — hormone(s), hormonal, fertility, pcos; urine_routine — urine, urinalysis, cue; urine_albumin — microalbumin, albumin creatinine ratio, acr, urine albumin; serology — serology, dengue, widal, hiv, hbsag, viral markers; pancreas — amylase, lipase, pancreatic.
- Units (`canonical_unit_spelling`): a unit string whose whole folded, whitespace-collapsed form is a `units.json` variant → its canonical spelling; otherwise the collapsed `pfold` text (free text); blank → null.
- `convert_unit(analyte_id, value, unit)` → `{unit, canonical_value, canonical_unit, status}`; `canonical_value = round4(value × factor + offset)` with `round4(x) = floor(x × 10000 + 0.5 + 1e-9) / 10000` (evaluate left to right in IEEE doubles). Status: `unmapped` (no analyte), `no_value` (`value_num` null), `unit_missing` (a unit-bearing analyte with no unit — a missing unit is never assumed), `unit_unknown` (not listed; free text included), `converted`. Dimensionless numeric analytes convert a value with no unit or unit `ratio` (canonical unit null). Only `converted` sets `canonical_value`/`canonical_unit`; otherwise the observation charts as its own series labelled with its unit (§21).

## 21. Trends
- `trend_series(observations, analyte_id)` → `{analyte_id, display_name, series: [{unit, convertible, points, band}], skipped_ids}`. Rows: that `analyte_id`, `state != rejected`, `excluded_from_trends = 0`, `observed_date` not NULL, ordered by `(observed_date, created_ms, id)`. A row with `canonical_value` joins the convertible series of its `canonical_unit`; else a row with `value_num` joins the series of its `unit` (null = "no unit"); else (qualitative, range values) its id goes to `skipped_ids`. Series order: convertible series first, then unit series, each by first appearance.
- Point `{date, value, value_text, unit, flag, ref_low, ref_high, record_ids, observation_ids}`: `value` = canonical value (or `value_num` in a unit series); convertible points convert `ref_low`/`ref_high` with the row's own unit (`convert_unit`), unit-series points keep them as printed. Rows of one series with the same date and the same value collapse into one point: the first row supplies `value_text`, `unit`, `flag` and the range; `record_ids` (distinct, in order) and `observation_ids` list every member. Same date with a different value → separate points.
- `band` = `{low, high}` of the most recent point that has at least one bound, else null.
- `mini_trend(trend, observation_id)` (record detail): the series point containing the observation and the points before it — a report shows its trend as of that report. Shown only when that is ≥ 2 points. `values` = the last ≤ 5 point values (older first) formatted with the analyte's `decimals` (default 2): half-up on the magnitude (`floor(|x| × 10^d + 0.5 + 1e-9) / 10^d`), fixed `d` decimals, `-` for negatives; `text` = values joined by ` → ` (U+2192), e.g. `7.2 → 8.4 → 9.7`. `change` = `{delta, unit, since_date}` with `delta` = the same rounding of `current value − previous point value`; `change_text` = sign (`+`, U+2212 `−`, none when the rounded delta is 0) + `|delta|` with `d` decimals + ` <unit>` (omitted for null) + ` since <previous point date as yyyy-MM-dd>` (the UI may localize the date for display; vectors compare the ISO form). Not shown → `{show: false, values: [], text: null, unit: null, change: null, change_text: null}`. "View full trend" is UI.

## 22. Related records (suggestions)
`suggest_relations(record, candidates, today, existing_links)` runs after extraction for the processed record. Descriptors: `{id, record_type, sort_date, archived, split_parent, panels (§20 of the record), report_name, analytes (distinct non-rejected analyte ids), doctors (normalized names of its doctor and referrer entities), facilities, follow_up_dates (non-rejected follow_up_date values)}`. Candidates are records with `sort_date` within ±180 days inclusive (index scan on `idx_records_timeline`). `today` is part of the port signature and unused by the v1 rules.
- Skipped: the record itself; an archived split parent (as record → no suggestions at all, or as candidate); a pair `(min id, max id)` that already has a `record_links` row of any origin/status (so a rejected suggestion is never re-created).
- Signals, summed per kind, reasons appended in this order:
  - both lab/imaging/diagnostic and (a shared panel → `same_panel`, and/or equal non-empty §8.1-normalized `report_name` → `same_report_name`) → `previous_report` 0.5, + 0.2 with ≥ 3 shared analytes (`shared_analytes`);
  - `|days| ≤ 30` and a shared doctor → `same_episode` + 0.4 (`same_doctor`); `|days| ≤ 30` and a shared facility → `same_episode` + 0.2 (`same_facility`);
  - one is a prescription dated 0–14 days after the other, a consultation note or discharge summary, sharing a doctor → `prescription_for` 0.6 (`prescription_after_visit`);
  - a `follow_up_date` of either within ±7 days of the other's `sort_date` → `follow_up` 0.6 (`follow_up_date`).
- `score = round2(min(1, sum))` (summed in the order follow_up, prescription_for, previous_report, same_episode); created when `score ≥ 0.6`; `kind` = the kind with the highest `round2` score, ties → follow_up, prescription_for, previous_report, same_episode. A same panel alone (0.5) is not enough.
- Ordered by score descending, then `|days|`, then candidate id; kept up to `5 − (existing suggested links of this record)`. Output links `{a_id, b_id, kind, origin: suggested, status: suggested, score, reasons}`.
- `split_from` 1.0 links are created at split acceptance (`status accepted`), not by this function.

## 23. Query parser additions (Phase 3)
`parse_query` output gains `analyte_conditions` and `analytes` (every Phase 2 vector now carries both keys; the Phase 2 cases `hemoglobin`, `reports where hemoglobin was low`, `high cholesterol`, `elevated tsh last year`, `sugar out of range` and `hba1c above 7` changed as described here — this supersedes the §17 note that comparisons stay terms).
- Tokens (§17) are `(kind, value, text, start, end)` over the folded query. New: a run of ASCII digits + `.` + ASCII digits that ends at a non-alphanumeric or the end is one `w` token (`1.2`); `>=`, `<=`, `>`, `<`, `≥` (→ `>=`), `≤` (→ `<=`) are `op` tokens. A decimal token that ends up as a term becomes its words (`1`, `2`), as in Phase 2; unused `op` tokens are dropped.
- Query aliases: every catalog alias as §8.1 words and as `analyte_words` (both index the analyte), except keys of ≤ 1 character and aliases made only of type/flag/state/stop words or §20 method words (so `blood`, `ct` never match). Longest alias at the position wins. Resolution of a shared alias: keep analytes listing the query unit (when given and any does), then non-urine analytes, then numeric analytes (each filter only if it keeps one); still ≥ 2 → not an analyte (plain terms).
- Rule order at a word token: dates (§17 1) → states → types → **analyte alias** → **flag + alias** → flags → people → stop words/terms.
  - `<alias> [was|is|were|are] <flag>` with flag ∈ low, high, elevated, raised, abnormal, abnormality, abnormalities, out of range, critical, normal → condition `{analyte_id, flag, op: null, value: null, unit: null, canonical_value: null, canonical_unit: null}`.
  - `<alias> [was|is|were|are] <op> <number> [<unit>]` with op token or above/over/greater than/more than (`>`), below/under/less than (`<`), at least (`>=`), at most (`<=`); number `[0-9]+(.[0-9]+)?`; unit = `match_unit` on the folded query after the number and its spaces (`7%`, `5.5 mmol/l`) → condition `{analyte_id, flag: null, op, value, unit, canonical_value, canonical_unit}`: no unit → `canonical_value = round4(value)` in the analyte's canonical unit; with a unit → §20 `convert_unit` (not convertible → both null, the condition matches nothing).
  - `<flag> <alias>` (`high cholesterol`, `low vitamin b12`) → flag condition.
  - A condition consumes its tokens (no terms, no global `flags`) and adds chip `{kind: analyte, text: folded query slice from the alias start to the end of the condition}`.
  - A bare resolved alias → its id appended to `analytes` (distinct) and its words to `terms` (stop words excluded); no chip. The Values group shows the latest observations of those analytes.
- Condition matching (store): observations with that `analyte_id`, `state != rejected`; flag `low` = low/critical_low, `high` = high/critical_high, `critical` = critical_*, `abnormal` = any of low/high/critical_*/abnormal, `normal` = normal; comparisons on `canonical_value`. Several conditions are AND-ed per record.
- Results gain a **Values** group: observation hits `{observation_id, record_id, analyte_id, display_name, value_text, unit, flag, observed_date}`.

## 24. Editing & traceability
- `edit_observation(obs, patch)`, patch keys each optional: `value`, `unit`, `ref_text`, `analyte_id`, `observed_date`, `excluded_from_trends`, `remove`, `now_ms`. Validation first, returning the observation unchanged with `error`: `unknown_analyte` (id not in the catalog), `bad_date` (not a valid `yyyy-MM-dd`), `empty_value` (blank value).
  - `remove: true` → `state = rejected`, `updated_ms` (nothing else).
  - `value` → whitespace-collapsed `value_text`; `value_num` = the §13 number (comparator values keep the number, `N-N` range values and qualitative words → null).
  - `unit` → §20 canonical spelling or free text (blank → null). `ref_text` → collapsed text (blank → null) and `ref_low`/`ref_high` re-parsed with the §13 range forms on the bracket-stripped text.
  - `analyte_id` → that id with `analyte_method = user`, or null with `analyte_method` null. `observed_date` → the date (or null) with `observed_date_method = user`. `excluded_from_trends` → 1/0.
  - Unit change (new canonical spelling ≠ old) without `ref_text` in the same patch: the printed range is in the observation's original unit, so `ref_low`/`ref_high` are converted old unit → canonical → new unit through the analyte's `units` factors (`round4`); when the analyte is unmapped or either unit is not listed for it (free text included), both bounds become null and `flag = unknown` — never a low/high against a range in another unit. `ref_text` always stays as printed. A `ref_text` in the same patch is taken as typed in the new unit (no conversion).
  - `flag` is recomputed (§13 resolution without a printed marker: computable value vs range, qualitative families vs `ref_text`, range values) when `value`, `ref_text` or the unit changed (unless it was just set to `unknown` above); `canonical_value`/`canonical_unit` are always recomputed.
  - Every successful non-remove edit sets `state = user` and `updated_ms`; `evidence`, `source_page`, `source_bbox`, `field_id` and `method` are kept.
- Add observation (user): analyte picker + value + unit + date (default = §19 `observed_date`); `method = user`, `state = user`, `observed_date_method = user`, no source; values computed as in an edit.
- Every observation, field and highlight with `source_page` opens the viewer at that page with `source_bbox` outlined; trend points open their record the same way.

## 28. Tool payloads
Reference: the Phase 4 section of `scripts/records_reference.py` — `records_search_payload(snapshot, args, selected_ids, today, date_order)`, `records_get_payload(snapshot, args, selected_ids)`, `records_series_payload(snapshot, args, selected_ids)` over a plain store snapshot (`records`, `fields`, `observations`, `highlights`, `pages`, `links`, `user_aliases`; list order = row order); vectors `test-vectors/coach_tools_payloads.json`. Payloads compare structurally (parsed JSON, §9.2 number/key rules), never as bytes. Common rules: `date` values are `sort_date` (search/get) or `observed_date` (series points); "best" = the §8.1 best non-rejected row (`doctor` = best `doctor_name` without `value_json.role = referrer`, `referrer` = best with it); missing → `null`. Date arguments: absent, `null` or `""` = no bound; otherwise a valid `yyyy-MM-dd` or `errors.bad_date` (`{value}` = the string, or the compact JSON of a non-string); `from > to` → `errors.date_order`.

`records_search` → `{"query": <string>, "count": n, "records": [{"record_id","title","date","record_type","facility","doctor","review_status","highlights":[<important highlight texts, max 3>]}], "values": [{"record_id","analyte","name","value","unit","flag","date"}]}`:
1. Arguments: a non-string `query` is `""`; `record_type` that is not a §3 value is ignored; `limit` default 10, whole numbers clamped to 1…20, anything else (strings, fractions, booleans) → 10.
2. `parse_query(query, today, date_order)` (§17/§23). The date range is the intersection of the parsed range with `from`/`to` (inclusive on `sort_date`; an empty intersection matches nothing). `record_type` narrows the parsed types: no parsed types → `[record_type]`; parsed types containing it → `[record_type]`; otherwise nothing matches.
3. Scope: with a selection, exactly the selected records; otherwise records whose `archived` equals the query's `archived` state.
4. Filters (AND): types; dates; `favorites`; `needs_review`; `source = received` → `source` in `share_in`/`open_in`; `flags` (§17, on `test_result` fields); `doctor`/`facility` → a non-rejected `doctor_name`/`facility` field whose §8.1 normalized words contain the name's normalized words as prefixes, in order; every §23 analyte condition (an observation of that analyte, state ≠ rejected, flag in the §23 set, or `canonical_value` compared when both canonical units are equal; a condition without a canonical value matches nothing).
5. No terms → timeline order (`sort_date`, `created_ms`, `seq` descending). With terms, every term must prefix-match a token of the record's FTS row in any column (FTS4 implicit AND), score = BM25 + recency, ordered by score descending, then timeline order. FTS row (`fts_row`): §17 columns, each folded; `people` = non-rejected doctor_name, doctor_specialty, facility, department, patient_name values; `clinical` = `record_type` with `_` → space (nothing for `other`), then report_name, test_result, diagnosis, symptom, medication, procedure values, then the display names of the record's distinct non-rejected analyte ids (sorted by id), duplicates removed; `body` = page texts by `page_index`; `notes_tags` = notes + tags; `highlights` = non-dismissed texts by (section, position); values joined with `\n`. Tokens = FTS4 `simple` tokenizer (runs of ASCII letters/digits and code points ≥ U+0080). BM25 (`bm25_pcnalx`) = matchinfo `pcnalx` computed over every record of the store: `n` rows; `a[c]` = (total tokens of column c + n/2) / n in integer arithmetic; `l[c]`; `tf` = this row's tokens starting with the term; `df` = rows with ≥ 1 such token in c; Σ weight[c] · max(ln((n − df + 0.5)/(df + 0.5)), 1e-6) · tf(k1 + 1)/(tf + k1(1 − b + b·l/max(a, 1))) with weights title 5, people 3, clinical 3, body 1, notes_tags 2, highlights 2, k1 1.2, b 0.75; recency = 0.15 × max(0, 1 − max(0, days)/730).
6. `records` = the first `limit` hits; `count` = the number of entries in `records`; highlights = the record's non-dismissed `important` highlights by position, max 3. `values` only when the query has bare analytes or analyte conditions: non-rejected observations of in-scope records whose analyte is a bare query analyte (any value) or satisfies one of the conditions, with `observed_date` inside the date range when the range has a bound; ordered by (`observed_date`, `created_ms`, `id`) descending, max 20; `analyte` = `analyte_id`, `name` = `raw_name`, `value` = `value_text`, `date` = `observed_date`. The Values group ignores `record_type` and the other record filters (§25).

`records_get` → `{"record_id","title","date","record_type","category","facility","doctor","referrer","patient_sex","patient_age","review_status","ai_mode_used","page_count","fields":[{"key","value","state","source_page"}],"test_results":[{"name","analyte","value","unit","ref_text","ref_low","ref_high","flag","state","source_page"}],"highlights":[{"section","text"}],"text": <string|null>}`:
- A non-string `record_id` is `""`. With a selection and an id outside it → `errors.not_selected`; unknown id → `errors.unknown_record`.
- `fields`: non-rejected rows in row order except `test_result`, `patient_name` and `location` (address); `value` = `value_text`, for `medication` the §15 medication line (`Metformin 500 mg · 1-0-1 · x 30 days`).
- `test_results` (`record_test_results`): when the record has any observation row, its non-rejected observations ordered by the row position of their field, then user-added observations by (`created_ms`, `id`) — `name` = `raw_name`, `analyte` = `analyte_id`, `value` = `value_text`; otherwise its non-rejected `test_result` fields (`analyte` null, `unit` = §20 canonical spelling, `flag` null → `unknown`).
- `highlights`: non-dismissed, ordered by (section, position).
- `text` only when `include_text` is exactly `true` (`record_text_excerpt`): per page by `page_index`, CRLF/CR → LF, every line is removed whose folded form has an identity/contact/ID label (patient, name, uhid, mrn, mr/ip/op/reg/regn no, registration, phone, mobile, mob, tel, telephone, contact, email, address, addr, aadhaar/aadhar, abha, pan no, passport, policy no, member id, id no, lab no, sample id, barcode, dob, d.o.b, date of birth, birth — whole words, `_RE_PII_LABEL`), a run of ≥ 10 digits optionally separated by single spaces or `-`, or a non-rejected `patient_name` value (§9.3 contains on normalized words); empty pages are skipped; pages joined with `\n\n`; first 2,000 code points; nothing left → `null`.
- Patient name, address, phone and IDs are never included in any tool payload (the contract check fails a vector whose payload contains the snapshot's patient name). Printed age and sex stay (`patient_age`, `patient_sex`).

`records_observation_series` → `{"analyte": <catalog id or null>, "display_name", "unit": <canonical unit or null>, "count": n, "points":[{"date","value","unit","canonical_value","flag","ref_low","ref_high","record_id","record_title","state"}]}`:
- Blank `analyte` → `errors.unknown_analyte`. Resolution (`resolve_series_analyte`): an exact catalog id, else §20 `map_analyte(argument)` with the store's user aliases and no panel/unit/kind context (so `Hb` → hemoglobin, a user alias name → its analyte).
- Rows: observations with state ≠ rejected, `excluded_from_trends` = 0, an `observed_date` inside `from`/`to`, whose record is selected (with a selection) or not archived (without). A resolved analyte takes its rows; when it has none, or the argument does not resolve, rows with `analyte_id` null whose `normalize_test_name(raw_name)` equals `normalize_test_name(argument)` (payload `analyte` null, `display_name` = the first row's `raw_name`, `unit` null); no rows → `errors.unknown_analyte`.
- Points: rows ordered by (`observed_date`, `created_ms`, `id`); a row with the same date and the same value (`canonical_value` when set, else `unit` + `value_text`) as an earlier row is dropped (copies of one report); the last 100 remain, oldest first. `value` = `value_text` as printed; `unit`, `ref_low`, `ref_high` are the row's own (printed unit); `canonical_value` in the analyte's canonical `unit`. Qualitative values are points too (`canonical_value` null).

Errors: `{"error": <message>}` using `errors.*` strings, placeholders filled in one pass. `errors.unavailable` is returned by the platform tool executor when access was turned off (or no records remain) while a tool call was in flight; it is not produced by the payload functions.

```
Notes:
<user notes>
AI highlights (verify against the original report):
- ...
Shared from Ayuvo. Values were read from the original document and may contain mistakes.
```
  - Records: the plan's `record_ids` in plan order; unknown ids are dropped, a repeated id is used once. `include_summary` false, or no id exists → `text` is null.
  - Line 1 is always `<title> — <date>` (title whitespace-collapsed, `date` = `sort_date`, U+2014); line 2 is the type label from the caller's `type_labels` (stored titles are never localized, this header is) plus ` · <facility>` when the `facility` field is selected and a facility exists.
  - `Doctor:` / `Patient:` = the §8.1 best non-rejected `doctor_name` (never a `value_json.role = referrer` row) / `patient_name`. `Dates:` prints the best row of each of `collection_date` Collected, `report_date` Reported, `visit_date` Visit, `prescription_date` Prescribed, `admission_date` Admitted, `discharge_date` Discharged, `follow_up_date` Follow-up — in that order, joined by ` · `.
  - Results = the §28 `test_results` of the record (its observations when it has any, else its non-rejected `test_result` fields), ordered as §29 (critical, low/high, abnormal, then the rest in report order). An item is `<name>: <value> <unit>` — missing parts are skipped and the `: ` disappears with them, so a row with only a name prints just the name — followed by ` (<flag word>, ref <ref_text>)` exactly as §29 builds it (one enclosing `()`/`[]` removed, the flag word only for flagged rows).
  - Medications: `<name> <strength>`, then `, <dose>`, `, <frequency>`, `, <duration>`, `, <instructions>` for each present part. Diagnoses and Recommendations are the non-rejected values in row order. Every value is whitespace-collapsed.
  - `Notes:` (with `include_notes`) prints the record's notes with CRLF/CR → LF, each line whitespace-collapsed and blank lines dropped. `AI highlights (verify against the original report):` (with `include_highlights`) prints the record's non-dismissed `summary` highlights — the validated AI summary of §15 — ordered by (`position`, `id`); the other highlight sections are already covered by Results, Medications and Recommendations.
  - A section with no data is omitted. Blocks are joined by an empty line, `---` and an empty line; the footer line ends the whole text once (never per record).
- **Redaction** of originals: pages are rasterized (long side 2,000 px) and every `blocks_json` line matching a selected redaction class is painted with an opaque black rectangle; output is a PDF (no text layer) named `<title>-redacted.pdf`. Reference `redaction_targets(snapshot, record_id, classes)` → `{record_id, classes, pages: [{page_index, lines: [{index, classes, box}]}], excluded_pages, warnings}`, vectors `test-vectors/redaction.json`; `index` is the 0-based position of the line inside `blocks_json` and `box` its `b` box inflated by 0.02 on every side in the normalized 0–1 box space (2 % of the page), clamped to 0…1 and `round4`-ed. Classes are listed in the order name, address, phone, patient_id, insurance_id, other_ids, both in the request echo and per line. Detection on the folded line text (§10):
  - `name` = the record's best non-rejected `patient_name`: its whole word sequence as a run of the line's words, or any of its parts of ≥ 3 characters as a word of the line.
  - `address` = an address label line (`address`, `addr`, `residence`, `residential`) and the following lines until a line with no letters or digits, at most 4 lines in all.
  - `phone` = a phone label (`phone`, `mobile`, `mob`, `tel`, `telephone`, `cell`, `contact`, `whatsapp`, `ph`), or — only on a line that is **not** a printed result line — a run of 7–15 digits made only of digits, spaces, `-`, `+`, `(` and `)` that is not a numeric date (`d-m-y`). So `+91 98765 43210`, `(022) 2345-6789` and `9876543210` match while `2026-09-13` and a 6-digit PIN do not. A line is a printed result line when it parses as a §13 lab row, or carries a number immediately followed (optional space) by a `units.json` unit, or is nothing but a printed numeric range (`4000 - 11000`, `1.5-4.1`; a tight range without a decimal point such as `2345-6789` stays a phone candidate). This keeps lab values and reference ranges readable — `Total WBC Count  8200 /cumm  4000 - 11000` is never painted — while a phone label always wins, so `Mobile 9876543210  Hemoglobin 7.6 g/dL` still is. Everywhere else the rule deliberately over-redacts: a bare `UHID 9876543210` or an 8-digit sample number is painted too.
  - `patient_id` / `insurance_id` = a line carrying one of the labelled forms (uhid, mrn, mr/reg/regn/registration/hospital/ip/op no, patient id/no / policy no or number, member id/no, claim no/id, tpa id/no, insurance id).
  - `other_ids` = a line with a generic id label (`id`, `no`, `number`, `ref`, `reference`, `barcode`, `code`, `serial`, `accession`, `sample id`, `lab no`) that also carries a word of ≥ 6 characters mixing letters and digits.
  - A page whose `blocks_json` is absent, blank, unparsable or not an array cannot be redacted, and neither can a page where a matched line has no usable `b` box: the page index goes to `excluded_pages` with the warning "Page N can't be redacted and was left out" (N is 1-based). An empty array is a page that is redactable but has nothing to paint. With no requested class nothing is detected and no page is excluded.
- Without redaction, originals are shared as the untouched file (whole document) or, for a page subset, a new PDF of those pages (iOS PDFKit copy keeps the text layer; Android re-renders, losing it — the UI says "Selected pages are shared as images").
- **Plan warnings** (reference `share_plan_warnings(snapshot, plan)` → `{warnings, pages, records}`, vectors in `redaction.json`, op `plan_warnings`). Each warning is `{code, record_id, page_index, text}` with these codes and strings (`{title}` = the record title, `{page}` = the 1-based page): `unknown_record` "A selected record is no longer available and was left out"; `no_original` "The original file of {title} is missing and was left out"; `page_missing` "Page {page} of {title} doesn't exist and was left out"; `page_not_redactable` "Page {page} can't be redacted and was left out"; `record_not_redactable` "No page of {title} can be redacted, so it was left out"; `text_layer_lost` "Selected pages are shared as images" (once, when a PDF is shared as a page subset without redaction; platform-specific, see §38); `redacted_text_layer_lost` "Redacted pages are shared as images" (once, whenever a redaction runs); `nothing_to_share` "Nothing is selected to share". `pages` lists the pages of each record that survive into the shared original.
- The share screen shows every item that will be shared, a page-1 preview of each produced file, then a final confirm. Files are written to the share temp folder (§2), deleted on next launch. `shared_count` +1 and `last_shared_ms` are updated per record on a successful share.

## 35. `ayuvo-records` archive
Zip (deflate), entries written in this order: `manifest.json`, `records.ndjson`, `pages.ndjson`, `fields.ndjson`, `observations.ndjson`, `highlights.ndjson`, `links.ndjson`, `entities.ndjson`, `record_entities.ndjson`, `tags.json`, `analyte_user_aliases.json`, then per record (in the `records.ndjson` order) `files/<record_id>/original.<ext>` and `files/<record_id>/thumb.jpg`, and finally `checksums.json`. Reference `archive_entry_names(snapshot, include_files)`.
- `manifest.json` (reference `archive_manifest(snapshot, platform, app_version, created_ms, time_zone, include_files)`): `{"format":"ayuvo-records","format_version":1,"schema_version":4,"app":"Ayuvo","app_version":"<x.y>","platform":"android|ios","created_ms":…,"time_zone":"<IANA>","record_count":n,"file_count":n,"total_file_bytes":n}` — keys in that order, `record_count` counts every record (archived included), `file_count`/`total_file_bytes` cover the `files/` members on disk. Readers reject `format_version > 1`.
- Every entry ends with a single LF. An `*.ndjson` line is one row as a compact JSON object (separators `,` and `:`, non-ASCII unescaped) with the column names of §8/§19/§33 in schema order and NULL or absent columns omitted; `manifest.json`, `tags.json` and `analyte_user_aliases.json` hold one compact JSON value. A column holding a JSON object — `value_json` — is written with **sorted keys** (§38), while the columns themselves stay in schema order. `records.seq` is the local FTS docid and is never exported. `pages.ndjson` carries `blocks_json` as a string.
- Row order (reference `archive_rows(snapshot)`): records by (`sort_date`, `created_ms`, `id`); pages by (`record_id`, `page_index`); fields and observations by (`record_id`, `created_ms`, `id`) so the row order inside a record survives the round trip; highlights by (`record_id`, `section`, `position`, `id`); links by (`a_id`, `b_id`); entities by (`kind`, `normalized_name`); `record_entities` by (`record_id`, `entity_id`, `role`). `tags.json` is `[{"id","name","record_ids"}]` (the `tags` and `record_tags` tables folded into one entry) ordered by the folded name then id, with `record_ids` in record order; `analyte_user_aliases.json` is `[{"normalized_name","analyte_id","created_ms"}]` ordered by `normalized_name`.
- Line cap 256 KB of UTF-8 per encoded line, and only `pages.ndjson` is ever truncated: the row keeps the longest prefix of its `text` (counted in code points) that still fits and gains `"text_truncated":true`; when the row does not fit even with an empty text, `blocks_json` is dropped first (`"blocks_truncated":true`) and the text is only cut if that is still not enough.
- `checksums.json`: `{"<entry name>": "<lowercase sha256>"}` for every entry except itself; a mismatch is a warning on import (the row/file is still imported), a `files/` member with no checksums entry is skipped.
- Reading (reference `read_archive_rows(entries)` → `{ok, error, error_text, manifest, rows, files, warnings, counts}`, vectors `archive.json` op `read`). Fatal, importing nothing: a missing or unreadable `manifest.json` (`manifest_missing`), a foreign `format` (`bad_format`), `format_version > 1` (`unsupported_version` — "This backup was made by a newer version of Ayuvo"). Everything else is a warning and the rest is still imported: `checksums_missing`, `checksum_mismatch`, `checksum_unlisted`, `file_unlisted` (the file is skipped), `entry_missing`, `entry_order`, `unknown_entry`, `bad_row` (a row that is not an object or lacks a required column is dropped), `unknown_columns` (dropped), `record_count_mismatch`.
- Import modes (reference `merge_plan(existing_snapshot, incoming_rows, mode)`, vectors `archive.json` op `merge`): **Merge** skips a record whose `id` exists (`existing_id`) or whose `checksum_sha256` matches an existing record (`existing_checksum`, with the matched id), and an id repeated inside the archive (`duplicate_in_archive`); **Replace** deletes all records, files and derived rows first (`deleted`, newest first). Child rows (pages, fields, observations, highlights, `record_entities`) follow their record and are skipped with it; a link is kept when both of its records exist after the import and at least one is new; entities are imported when a kept `record_entities` row references them (the store upserts by (`kind`, `normalized_name`)); a tag keeps only its kept `record_ids`; an alias whose `normalized_name` already exists is skipped on Merge. Imported records keep their ids, dates and user states; `processing_status` becomes `ready`, review states are preserved; FTS is rebuilt at the end; a record with no `files/` original gets `file_path = NULL` and `processing_error = file_missing`.
- Export streams entry by entry (never the whole zip in memory), shows progress, and is written to the share temp folder, then handed to the system share sheet / Files. Export honours "include original files" (default on; off = metadata only, no `files/` entries, `file_count = 0`).
- `records_backup_state` is updated after export/import.

## 37. Storage management
Settings › Health Records › Storage shows sizes computed in the background: Documents (originals by `file_type`: PDFs, Images, Text), Thumbnails, Render cache, Database, Backups (archives still in the share temp folder), Total; plus record and page counts. Actions, each with a confirmation and a progress state: **Clear generated cache** (render cache + share temp; originals and thumbnails untouched), **Rebuild thumbnails**, **Rebuild search index**, **Find duplicates** (runs §15 near-duplicate detection across all records and opens Needs Review), **Reprocess all** (re-runs the pipeline from `text`, keeping user/confirmed values per §8.1). Originals are never deleted by any action.

## 38. Phase 5 clarifications
- Summary delivery: the summary is shared as plain text — a `<title> summary.txt` file plus the same text as the share sheet's text item. No PDF summary (the §3.12 plan note is superseded).
- The fixture archive's `blocks_json` boxes (§35.1) are evenly spaced placeholders and do not line up with the glyphs in its generated PDFs; a visual redaction check on fixture records will look misaligned even when the implementation is exact. Verify redaction visually on a pipeline-processed record instead.
- Archive round trips are compared **structurally** (§9.2 rules: numbers by value), never byte-for-byte: a SQLite REAL column cannot preserve `96` vs `96.0`.
- `value_json` is stored in §8 key order but **exported with sorted keys** on both platforms, so archives are stable and portable.
- `SHARE_WARNINGS.text_layer_lost` is platform-specific: the reference always emits it for a page subset without redaction; a platform whose page copy keeps the text layer (iOS PDFKit) filters it out. Android keeps it.
